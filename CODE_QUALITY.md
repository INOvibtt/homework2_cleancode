# Аналіз якості коду навчального проєкту

Основа: гілка `main` репозиторію `goitProjects/java-dev-homework-module-14-code-quality`, консольна гра «Хрестики-нулики».

## Що було в початковому коді

- Уся програма знаходилася в одному методі `main` (близько 85 рядків логіки): складно тестувати й змінювати окремі правила.
- Неінформативні назви `scan`, `rand`, `box`, `i`, `winner` приховували призначення змінних; для стану гри використовувалися магічні числа 1, 2, 3.
- Перевірка перемоги була скопійована двічі — для `X` та `O` — у вигляді довгих логічних виразів.
- `Scanner.nextByte()` аварійно завершував гру на нечисловому або завеликому введенні. Вичерпання вводу не оброблялося.
- При першому виведенні показувалися цифри, а потім поле очищувалося: друк і ініціалізація були змішані.
- Не було тестів і `.gitignore`; Maven-артефакти в `target/` не ігнорувалися Git.

## Рефакторинг

Ініціалізацію поля, введення, хід комп'ютера, вивід і визначення переможця розділено на короткі методи. Вісім виграшних комбінацій описано один раз і використовуються для обох гравців. Для випадкового ходу використовується вибір серед вільних клітинок; для перевірки правила можна передати керований `Random`. Додано перевірку введення, тест на перемогу гравця та комп'ютера, `.gitignore`.

## SonarLint

В IntelliJ IDEA: **Settings → Plugins → Marketplace → SonarQube for IDE** (раніше SonarLint), встановити плагін і перезапустити IDE. Відкрити `src/main/java/App.java`, переглянути підкреслені проблеми та вкладку **SonarQube for IDE**. Аналізувати вихідну версію можна через `git show main:src/main/java/App.java`; порівняти її з поточною гілкою. Плагін не запускався в цій роботі автоматично: наведені вище проблеми знайдені під час ручного аналізу, а не приписані звіту SonarLint.

## Перевірка

`mvn test` запускає JUnit-тести; `mvn package` збирає проєкт. Для ручної гри: `java -cp target/classes App`.
